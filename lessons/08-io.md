# 08 — Streams, files, and data boundaries

**Goals:** process text safely, close resources, distinguish parsing from reading

## Prerequisite recap

## Streams and formatting

A stream is an input/output abstraction. `*standard-input*`, `*standard-output*`,
and `*error-output*` are special variables naming the usual streams. `format`
uses directives: `~A` prints aesthetically, `~S` prints with readable escaping,
`~D` prints an integer, `~%` emits a newline, and `~~` prints a tilde.

```lisp
(format t "~A has ~D tasks.~%" "Ada" 3)
(format nil "~S" "a quoted string") ; a string containing escaped quotation marks
(with-output-to-string (out)
  (format out "one~%two~%"))
```

`format` sends output to a stream argument; `t` means the usual standard output,
whereas `nil` collects the output into a returned string. Its control string's
directives consume subsequent arguments in order. `with-output-to-string` binds
`out` to a temporary string-output stream, executes its body, and returns the
collected text rather than the body's last value. `out` is our local stream name.

### Redirecting output by rebinding a stream variable

`format t` writes to whatever `*standard-output*` currently names. Because it is
a special variable, a temporary `let` binding redirects output for every call
made inside the `let`, without changing those functions:

```lisp
(defun print-banner ()
  (format t "== Report ==~%"))

(with-output-to-string (out)
  (let ((*standard-output* out))
    (print-banner))) ; "== Report ==
                     ; " (the banner text, captured instead of printed)
```

This is the temporary rebinding of a shared setting from
[Lesson 03](03-functions.md#top-level-variables-for-shared-settings), applied to
a stream. When the `let` exits, output goes to the terminal again. It is a
convenient way to test printing functions. The optional
[dynamic-scope reference](../optional/DYNAMIC-SCOPE.md) explains the binding rules.

Use a constant format control string for untrusted text:
`(format t "~A" user-text)`, not `(format t user-text)`.

## Text files and EOF

**EOF** means end-of-file. `with-open-file` binds a chosen stream name to an
opened file for its body. `:direction :input` opens for reading, while
`:direction :output` opens for writing. These keywords are options and option
values, not variables.

```lisp
(defun count-lines-in (in)
  "Return the number of lines read from stream IN."
  (loop for line = (read-line in nil nil)
        while line
        count t))

(defun count-lines (path)
  "Return the number of lines in the file at PATH."
  (with-open-file (in path :direction :input)
    (count-lines-in in)))
```

`with-open-file` closes the stream on normal return and nonlocal exit. An empty
line is `""`, which is true, so it is not confused with EOF. `read-line` can
return a second value indicating a missing terminating newline; the count above
does not need it. File external formats are implementation-dependent; on SBCL
you can explicitly use `:external-format :utf-8` when UTF-8 is your chosen format.

The arguments in `(read-line in nil nil)` are stream, EOF-error flag, and EOF
replacement value. The first `nil` requests a value instead of an error at EOF;
the second makes that value `nil`. `loop for line = ...` computes the next line
each iteration; `while line` stops on `nil`, and `count t` adds one for each
iteration reached. Unlike `collect`, `count` returns a number rather than a list.

```lisp
(with-open-file (out "work/report.txt"
                     :direction :output
                     :if-exists :supersede
                     :if-does-not-exist :create)
  (format out "A new report~%"))
```

`:supersede` replaces an existing file: do not use it casually on valuable data.
Production persistence may need temp-file replacement, backups, synchronization,
and crash recovery. The capstone documents a simpler single-process policy.

`:if-exists` selects the existing-file policy; `:if-does-not-exist :create`
permits creating a missing file. [Lesson 11](11-conditions.md) explains nonlocal
exits and cleanup; `with-open-file` handles stream closure without requiring you
to write that machinery here.

`count-lines-in` separates the counting algorithm from opening a file. Test it
without disk access using a string-input stream:

```lisp
(with-input-from-string (in "last line without newline")
  (count-lines-in in)) ; 1
```

`with-input-from-string` binds `in` to a stream reading the given string. Try
`""` for zero lines, and `(format nil "~%")` for one empty line. Then use a
small scratch file to test the `count-lines` wrapper.

## Parse user input, don't evaluate it

For an integer, use `parse-integer`. With default `:junk-allowed nil`, surrounding
whitespace is allowed but nonnumeric trailing junk is an error.

```lisp
(parse-integer " 42 ")            ; primary value 42
(parse-integer "42x" :junk-allowed t) ; 42 and index 2; not strict validation
```

For exercise 2, call `parse-integer` with its strict defaults, check positivity,
and signal `(error "Expected a positive integer")` when the parsed number is
not positive. Keep intentional failure calls separate from your normal script
until Lesson 10's expected-error tests.

## Later reference: Lisp data files and EOF markers

**Return after Lesson 09, before adding capstone persistence.** Text files do
not require the Lisp reader. Use `read-line` for lines and `parse-integer` for
numbers; never execute input with `eval`.

An **s-expression** is an external representation of Lisp data, such as a symbol,
number, or nested list. `read` parses such objects, not general text. The Lisp
reader can perform actions: for example, `#.` enables read-time evaluation when
`*read-eval*` is true. Never
use `eval` on user data. For trusted local s-expression files, bind
`*read-eval*` to `nil`, constrain expected data shapes, reject extra objects, and
use an isolated reader package where appropriate. **This is still not a secure
parser for hostile files**: huge objects, reader features, symbol interning, and
resource exhaustion remain concerns. Prefer a dedicated bounded parser/format
for adversarial data. The reference capstone accepts only local trusted files.

For `read`, `nil` can be legitimate data, so use a unique EOF marker.
`gensym` creates a fresh, uninterned symbol; its optional string supplies a naming
prefix, not the symbol's identity. We use the fresh symbol as a marker that
ordinary file data will not accidentally equal. [Lesson 09](09-systems.md)
explains interning/packages, and [Lesson 13](13-macros.md) reuses `gensym` for
macro-generated variable names. The example reads from a string stream, as
in the line-counting tests above.

```lisp
(let ((eof (gensym "EOF"))
      (*read-eval* nil))
  (with-input-from-string (in "nil")
    (let ((value (read in nil eof)))
      (if (eq value eof) :empty value)))) ; NIL, not :EMPTY
```

`read` has the same stream/EOF-error/EOF-value argument positions shown for
`read-line`, but returns a parsed Lisp object rather than a line of text.
`:empty` is an application-chosen result label. `read-from-string` is another
reader entry point: it reads an object directly from a string and also returns
the index after it; it is not a safe substitute for a constrained input parser.

## Pathnames

Common Lisp pathnames model names, types, directories, and other components.
`probe-file` checks existence, `truename` resolves an existing pathname, and
`merge-pathnames` combines components with defaults. A pathname is not guaranteed
to behave like naive string concatenation. Paths containing spaces need quoting
in shell commands, independently of Lisp string escaping.

`user-homedir-pathname` returns the user's home directory pathname; the optional
Quicklisp setup combines it with a relative pathname using `merge-pathnames`.
`namestring` renders a pathname as a filename string. `close` explicitly closes
a stream and `delete-file` removes a file; the capstone tests use those on
temporary test files only. `write-line` writes a string plus newline to a stream.
